Резюме изменений

Добавлена компонентa "Глобальная привлекательность места" (Global Place Conversion) — сигнал от толпы, учитывающий, как часто место попадало в сгенерированные маршруты и как часто такие маршруты сохраняли разные пользователи.

Что конкретно сделано

- Собирается агрегированная статистика по месту (по place_id): количество попаданий в маршруты (generated) и количество сохранений (saved).
- Вычисляется сглаженная конверсия места: placeConversion = (saved + 1) / (generated + 2).
- Конверсия применяется в базовой оценке места как аддитивный компонент: baseScore += weight * placeConversion.
- Значение веса вынесено в константу `placeConversionWeight` (по умолчанию 0.18). Рекомендуется регулировать в диапазоне ~0.12–0.22.
- Добавлен метод репозитория для получения агрегатов по списку place_id, и реализована SQL-агрегация в адаптере БД.
- Тесты и вызовы функции `buildRecommendationCandidates` обновлены под новую сигнатуру.

Как это работает (формула)

- Старый базовый скор (пример):
  baseScore = preferenceScore + 0.4 * proximityBonus - foodPenalty + placeScoreAdjustments

- Новый базовый скор (добавлен component crowd CTR):
  placeConversion = (saved + 1) / (generated + 2)
  baseScore = preferenceScore + 0.4 * proximityBonus - foodPenalty + placeScoreAdjustments + (placeConversionWeight * placeConversion)

Примечания по сглаживанию

- Сглаживание (Laplace-like) защищает от аномалий: место с 1 показом и 1 сохранением не получит 100% конверсию. Формула даёт разумную начальную оценку для редко встречающихся мест.

Влияние на рекомендации (на практическом уровне)

- Что усиливается:
  - Места, которые показываются часто и действительно сохраняются пользователями, получают заметный буст и легче попадают в итоговые маршруты.
  - Это помогает учитывать «схожесть вкусов толпы»: популярные у других места приходят выше, даже при средней персональной preferenceScore.

- Что ослабляется:
  - Локальные аномалии (единичные сохранения редких мест) защищены сглаживанием, поэтому не будут доминировать.

- Ожидаемый эффект:
  - Повышение процента попавших в маршрут мест с высокой реальной конверсией у других пользователей.
  - Более быстрая конвертация коллективного сигнала в улучшение качества рекомендаций для новых/малораспознанных пользователей.

Производительность и масштабирование

- Текущая реализация делает агрегирующий SQL-запрос на список place_id, полученных из результатов поиска (в Execute()). Для большого числа кандидатов/высокой частоты вызовов это может быть узким местом.
- Рекомендации по оптимизации:
  - Предварительная периодическая агрегация (materialized table или nightly job) с хранением готовой конверсии для всех place_id и чтением из неё по списку id.
  - Кеширование недавно запрошенных placeConversion значений (Redis) для снижения нагрузки.
  - Ограничить число place_id в одном запросе (например, топ-100 по расстоянию) — сейчас реализация уже отфильтровывает и дедуплицирует.
